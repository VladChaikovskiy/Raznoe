# Katana by Vlad_i_c

Android-приложение для управления комбоусилителем **BOSS Katana** по
**USB-кабелю** — открытый аналог официальных Katana Librarian / BOSS Tone Studio.
Подключаешь телефон к комбику кабелем USB-C, управляешь усилителем, эффектами,
каналами, сохраняешь пресеты. Минусовку при этом можно гнать в комбик
**по Bluetooth** — управление и звук идут по разным каналам и не мешают друг другу.

> Интерфейс — русский. Ядро (протокол/USB) — Kotlin, покрыто автотестами.

---

## ⚠️ Честный статус (прочитай обязательно)

Протокол Katana не публичный — он расшифрован сообществом. Реализовано на основе
открытых проектов (snhirsch/katana-midi-bridge, katana-dev) и исследования
форумов/официальных материалов.

1. **Framing и контрольная сумма** (`F0 41 00 00 00 00 33 …`, команды `11`/`12`,
   Roland checksum) — **подтверждены и покрыты тестами** (сборка кадров, парсинг,
   2-байтовые параметры, упаковка USB-MIDI, Identity — тесты проходят), как и
   конвейер пресетов, валидация значений и **карта адресов, сверенная со
   спецификацией** (всего 64 теста).
2. **Карта адресов MkII сверена со спецификацией построчно** — см.
   [docs/katana-address-map.md](docs/katana-address-map.md). Именно эта сверка
   нашла причину «контрабасного» звука (блок усилителя был сдвинут на одну
   позицию, тип усилителя не писался вообще). **Точные адреса Gen 3 сообществом
   ещё дореверсиваются** и в открытом виде отсутствуют. Поэтому:
   - приложение шлёт **Identity Request** при подключении и показывает ответ
     (по нему поймём model ID твоего Gen 3);
   - архитектура сделана как **сменный профиль** (model ID + таблица адресов в
     одном файле [`KatanaParams.kt`](app/src/main/java/com/raznoe/katana/protocol/KatanaParams.kt));
   - параметры, не подтверждённые для Gen 3, помечены **«(?)»**;
   - вкладка **«Консоль»** даёт инструмент, чтобы найти реальные адреса Gen 3.
3. **На реальном железе не тестировалось** (у сборщика нет ни комбика, ни
   телефона). Первый запуск с усилителем — за тобой; дорабатываем по логам.
4. **iOS не поддерживается** — по кабелю к Katana там подключиться нельзя без
   MFi. Официальное приложение Gen 3 на телефоне работает по Bluetooth (адаптер
   BT-DUAL), а не по кабелю; по кабелю реально только на Android.

## Как подключить к комбику

1. **Включай Katana, удерживая кнопку [BOOSTER]** — так активируется режим
   **USB-MIDI** (без этого USB отдаёт только звук, без управления).
2. Соедини **USB-C телефона → USB-порт комбика** (при необходимости — переходник OTG).
3. Открой приложение → оно найдёт устройство Roland (VID 0582) и попросит
   разрешение на USB → **OK**.
4. Вверху появится «● …» и строка **ID: …** (ответ Identity — пришли мне её).

При подключении приложение выполняет рукопожатие (Identity + announce ×2 →
включение режима редактора `7F 00 00 01`=01 → пауза 100 мс → чтение состояния),
как это делает официальное ПО.

Если кабель дёрнули и связь пропала, приложение **переподключается само** —
до 5 попыток с растущей паузой (1.5 / 3 / 4.5 … секунды). Ручное «Отключить»
эти попытки останавливает.

## Звук минусовки по Bluetooth

Katana Gen 3 умеет принимать звук по Bluetooth. Так это и задумано использовать:

1. Подключи комбик как Bluetooth-аудио в **системных настройках телефона**
   (приложению для этого никаких разрешений не нужно).
2. Кабель USB-C оставь подключённым — по нему идёт управление (пресеты, ручки).
3. На вкладке **«Джем»** выбери выход: **Авто** (Bluetooth → USB → телефон),
   либо жёстко **Bluetooth / USB (комбик) / Телефон**. Рядом видно, что реально
   доступно и куда сейчас идёт звук.

Приложение следит за маршрутом само:

- Bluetooth подключился **после** запуска трека — звук переедет в комбик на ходу.
- Bluetooth пропал — трек встаёт на **паузу** (а не орёт из динамика телефона)
  и продолжается сам, когда связь вернётся.
- Позвонили / пришло уведомление — пауза и автоматическое возобновление.
- Экран погас или свернул приложение — играет дальше: воспроизведение держит
  **foreground-сервис** с уведомлением (Играть / Пауза / Стоп) и partial wake lock.

Отдельный плюс: Bluetooth убирает **аналоговую петлю по земле**. Если минусовка
шла в комбик кабелем в AUX IN, а телефон одновременно висел на USB, между ними
получалась земляная петля — это ровно тот гул/фон, который слышно между нотами
(и та же петля наводила фантомные нажатия кнопок, из-за чего в приложении и
появился тумблер «блокировать кнопки телефона»). По Bluetooth гальванической
связи нет, и фон уходит вместе с ней.

## Что умеет (интерфейс)

Интерфейс оформлен в стиле приложения **NUX Mighty Amp**: чёрный фон, оранжевый
акцент, круглые ручки-дуги, горизонтальная сигнальная цепочка из цветных блоков,
нижняя навигация. Четыре экрана:

- **Патч** — заголовок устройства, статус подключения, круглые кнопки каналов
  (Panel/CH1–CH4), **сигнальная цепочка** GATE → BST → AMP → MOD → FX → DLY → RVB
  (тап по блоку открывает его редактор). В редакторе блока: Off/On, выбор типа
  эффекта чипами и параметры круглыми **ручками** (gain/EQ у ампа; drive/tone/level
  у бустера; time/feedback/level у delay; type/time/pre-delay/density/level у reverb).
- **Пресеты** — 54 пресета: 20 помеченных **★** — оригинальные демо-патчи
  BOSS/JuCaNeRy, расшифрованные из `.kat` файлов Katana Librarian, остальные —
  мои версии в духе известных названий (AC/DC, Pink Floyd, Metal, Jazz, Fusion…).
  «Загрузить» отправляет тон на комбик **целиком** — см. ниже.
- **Джем** — вся музыка с телефона подтягивается сама (см. ниже), плюс поиск по
  названию и артисту. Плеер: play/pause, перемотка, луп, скорость
  (1.0/0.75/0.5/1.25×), выбор выхода (Bluetooth / USB / телефон), громкость
  минусовки и гитары рядом.
- **Библиотека** — сохранение/загрузка своих тонов в JSON на телефоне.
- **Консоль** — сырой SysEx, чтение блоков и лог TX/RX (для уточнения адресов Gen 3).

## Минусовки: музыка телефона подтягивается сама

При первом заходе на вкладку «Джем» приложение просит доступ к музыке, после
чего **вся музыка с телефона появляется в списке сама** — ничего добавлять
руками не нужно. Список читается из `MediaStore` (та же медиатека, которой
пользуются все плееры), с названием, артистом и длительностью; сверху поиск по
названию/артисту, кнопка **⟳** перечитывает медиатеку после того, как ты
скинул на телефон новые файлы. Рингтоны, будильники и звуки уведомлений
отфильтрованы (`IS_MUSIC != 0`).

Кнопка **«+ файл»** осталась для файлов вне медиатеки (например, на SD-карте в
папке, которую медиасканер не видит) и теперь умеет выбирать **сразу несколько**
файлов. Такие треки идут первыми в списке и удаляются крестиком; треки из
медиатеки крестика не имеют — они всё равно вернутся при следующем чтении.

### Почему раньше MP3 не добавлялись

Две причины, обе исправлены:

1. Стандартный контракт `OpenDocument` **не запрашивает постоянное разрешение**
   на URI (`FLAG_GRANT_PERSISTABLE_URI_PERMISSION`), поэтому
   `takePersistableUriPermission` падал с SecurityException, исключение
   заглушалось, и доступ к файлу жил только до перезапуска процесса. Теперь
   разрешение запрашивается сразу — см. [`PickAudio.kt`](app/src/main/java/com/raznoe/katana/ui/PickAudio.kt).
2. Активность была объявлена как `launchMode="singleTask"`, из-за чего она
   становится корнем задачи, а корню задачи система может отдать **отменённый
   результат** при запуске другого приложения за результатом — выбор файла
   молча не добавлял ничего. Теперь `singleTop`: авто-запуск по USB-кабелю
   (`onNewIntent`) работает так же, а результаты выбора не теряются.

Список рисуется через `LazyColumn`: в медиатеке легко несколько сотен треков, и
композиция всех строк сразу заметно тормозила вкладку.

## Найденная причина «контрабасного» звука

Симптомы были: на clean звук бубнящий, как контрабас; пресеты не отличались друг
от друга; при этом ручки EQ отзывались. Всё это — **одна ошибка в карте адресов**,
найденная сверкой с [реверс-инжиниринговой спецификацией SysEx](docs/katana-address-map.md).

Блок усилителя начинается с `00 00 04 20`, и **тип усилителя стоит первым**:

| Адрес | Параметр |
|---|---|
| `00 00 04 20` | **тип усилителя** (0 Acoustic, 1 Clean, 2 Crunch, 3 Lead, 4 Brown) |
| `00 00 04 21` | Gain |
| `00 00 04 22` | Volume |
| `00 00 04 23` | Bass |
| `00 00 04 24` | Middle |
| `00 00 04 25` | Treble |
| `00 00 04 26` | Presence |
| `00 00 04 27` | ручка Booster/Mod |

В приложении блок начинался с `04 21`, то есть **всё писалось на одну позицию
выше**: gain уходил в Volume, bass — в Middle, presence — в байт цепочки
Booster/Mod (вот откуда посторонние эффекты), а **реальный адрес типа усилителя
не писался никогда**. Комбик оставался на том характере, что выбран физически —
если это Acoustic, электрогитара идёт через симулятор акустики, и получается
ровно тот бубнящий контрабас, которого не победить никаким EQ. Ручки при этом
работали, просто каждая крутила соседний параметр.

Вторая ошибка того же корня: список типов усилителя содержал шестой,
несуществующий «Pushed» на индексе 2 — типов у комбика **пять** (0…4). Из-за
этого наш Crunch выбирал Lead, Lead выбирал Brown, а Brown (5) был вне
диапазона. Значения во всех пресетах пересчитаны.

Заодно исправлено по спецификации: выбор канала посылал **один** байт вместо
двух (`00 xx`), переключатели блоков теперь идут documented-CC (16 Boost/Mod,
17 Delay/FX, 18 Reverb) — потому что BOOST/MOD это одна ручка с двумя
диапазонами и SysEx-переключатель работает только для активного; Delay Effect
Level имеет диапазон 0…120, а Reverb Density 0…10, а не 0…100.

## Три способа получить звук как в Librarian

1. **Каналы комбика (самый надёжный).** Разложи в Librarian патчи по CH1–CH4 —
   на вкладке «Пресеты» они переключаются один в один. Звук берётся из комбика,
   приложение только просит переключить канал (Program Change + SysEx recall).
2. **«Снять тон с комбика»** («Библиотека»). Настроил звук — приложение читает
   байты комбика как есть и потом возвращает их точно такими же. Спецификация
   прямо называет это корректным способом делать виртуальные пресеты.
3. **Пресеты приложения** — 54 тона со своими значениями, и под каждым
   «▾ Подстроить» с ручками. Это единственный способ, который зависит от
   правильности карты адресов.

## Как устроены пресеты (почему они чистые и грузятся целиком)

Каждый пресет прогоняется через один конвейер (`FactoryPresets.finish`), который
даёт три гарантии:

1. **Полнота.** Пресет содержит значение для **каждого** параметра из
   `KatanaParams.ALL`. Раньше отправлялись только те параметры, которые пресет
   упомянул, а остальное доставалось от предыдущего тона — отсюда и «пресет не
   загрузился», и посторонний фон от чужого эффекта, оставшегося включённым.
2. **Валидность.** Каждое значение — код, который комбик действительно
   поддерживает (`KatanaParams.sanitize`). В списках типов есть пропуски
   (у Delay, например, нет типа 10), и неподдерживаемый код оставлял блок в
   неопределённом состоянии.
3. **Только то, что нужно для работоспособности патча.** Direct Mix у
   включённых delay/reverb выставлен в 100, чтобы сухая гитара не пропадала из
   микса. Блоки **Mod/FX включаются только с теми типами, которые мы умеем
   настраивать** (Comp, Limiter, Graphic EQ, Chorus, Phaser, Flanger, Tremolo,
   Rotary, Uni-V, Vibrato, Guitar Sim, AC Guitar Sim): для Gen 3 у нас
   реализованы только тип и вкл/выкл блока, поэтому включённый Wave Synth /
   Ring Mod / Humanizer / Slicer играл с настройками от прошлого патча — это и
   был основной источник «фона».

**Что конвейер НЕ делает — и почему.** Ограничители gain/presence/treble,
принудительный high cut в delay/reverb и шумодав на каждом пресете раньше жили
здесь же, и вместе они превращали чистые тоны в глухую, задушенную версию себя —
совсем не то, что в Librarian. Убрано:

- **Шумодав только на реально перегруженных тонах.** Порог считался от ручки
  Gain, а это неверно дважды: Clean-канал на Gain 80 всё равно чистый и тихий,
  а порог 45…60 душит затухание каждой ноты. Теперь решает характер усилителя
  (Lead/Brown → порог 27, Pushed/Crunch → 20, плюс 7 если бустер с drive ≥ 30),
  а Clean и Acoustic не трогаются вообще. Если демо-патч в Librarian шёл с
  выключенным шумодавом — он и останется выключенным.
- **Фильтры по умолчанию — Flat.** «Нейтральное» значение high cut подрезало
  верх у каждого пресета, который его не задаёт.
- **Импортированный патч сохраняет свои gain, EQ, уровни и фильтры**, какими бы
  крайними они ни выглядели (Demo 2 идёт с gain 93, Fusion Lead с presence 100 —
  так в Librarian, так и отправляется).

Единственное исключение — **Level (громкость патча)**: у 12 расшифрованных демо
он лежит в районе 19…32, и такой патч вызывается практически как тишина (это и
читается как «пресет не загрузился»). Такой Level поднимается до 55 — только
вверх, никогда вниз — и об этом честно написано в подписи пресета
(«Level поднят 19→55»).

Отправка тоже переделана: пресет уходит **одним атомарным пакетом** в порядке
«сначала ручки и типы, потом тумблеры» — блок включается уже настроенным, а не
с уровнем от прошлого пресета. Новая загрузка отменяет предыдущую, если та ещё
в полёте (раньше два быстрых нажатия смешивались в третий тон). На Gen 3, пока
комбик не сообщил слоты FX-BOX, значение пишется во все три слота-кандидата —
иначе запись молча уходила «не туда».

Внизу экрана «Пресеты» видно результат: сколько сообщений отправлено, и если
загрузка прервалась — предложение нажать ещё раз.

## Снятие логов для адресов Gen 3 (метод diff)

1. Вкладка **«Консоль» → «Прочитать блок»**: адрес `60 00 00 30`, размер `16`.
2. Запиши строки **RX** из лога.
3. Покрути **физически** одну ручку на комбике (например, Gain).
4. Снова «Прочитать блок».
5. Пришли оба RX — по изменившемуся байту определю точный адрес, впишу в
   `KatanaParams.kt` и поставлю `verified = true`.

## Архитектура

```
app/src/main/java/com/raznoe/katana/
├── protocol/
│   ├── KatanaSysEx.kt   — framing, checksum, Identity/handshake, парсинг (ядро, тесты)
│   └── KatanaParams.kt  — ПРОФИЛЬ УСТРОЙСТВА: адреса + типы эффектов (правится здесь)
├── usb/
│   ├── UsbMidiPacketizer.kt — SysEx ↔ 4-байтовые USB-MIDI пакеты (CIN 0x4–0x7)
│   ├── UsbMidiConnection.kt — USB Host API: интерфейс, bulk in/out, фоновое чтение
│   └── KatanaController.kt   — очередь с пейсингом, handshake, setParam, каналы, чтение
├── audio/
│   ├── JamPlayer.kt     — плеер минусовки: маршрутизация Bluetooth/USB, focus, авто-возврат
│   └── JamService.kt    — foreground-сервис: играет при погашенном экране
├── model/               — пресеты (конвейер finish), медиатека телефона, список треков
├── KatanaApplication.kt — запись стека последнего падения в файл
├── KatanaViewModel.kt   — состояние, декодирование блоков, авто-переподключение USB
├── MainActivity.kt      — разрешение USB, авто-подключение по кабелю
└── ui/                  — Compose UI (5 вкладок) + тема
```

**Транспорт.** Katana несёт стандартные USB-MIDI 1.0 пакеты по bulk-эндпоинтам.
Приложение claim-ит интерфейс через USB Host API (фильтр по Roland VID `0x0582`,
PID любой — Gen1/MkII/Gen3 разные), упаковывает SysEx в USB-MIDI пакеты, читает
ответы в фоновом потоке. Отправка идёт через очередь с паузами (запись ~4 мс,
чтение ~30 мс, пресет ~12 мс на сообщение), чтобы не флудить комбик и не
блокировать UI.

**Стабильность.** Что сделано, чтобы приложение не падало и не «зависало»:
USB-обрыв разбирается полностью (мёртвый sender + незакрытый интерфейс больше не
остаются) и связь поднимается заново сама; ручки коалесцируются по адресу, так
что протяжка не переполняет очередь; счётчики TX/RX и логи не пишутся в состояние
Compose на каждый пакет; плеер живёт вне ViewModel, переживает пересоздание
Activity и держит foreground-сервис; все обращения к MediaPlayer защищены от
IllegalStateException, а ошибка воспроизведения один раз молча восстанавливается
с той же позиции. Стек последнего падения пишется в файл и показывается на
экране «Патч» с кнопкой «Скопировать» — телефон в репетиционке к logcat не
подключён, и иначе о падении нечего было рассказать.
